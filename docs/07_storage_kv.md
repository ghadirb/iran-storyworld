# ذخیرهٔ ویدیوها روی KV چندحسابی (بدون R2)

R2 بدون ثبت کارت بانکی فعال نمی‌شود (خطای `10042`)، پس ویدیوها و پوسترها در **Cloudflare Workers KV** نگه‌داری می‌شوند.

## محدودیت‌های رایگان هر حساب (طبق مستندات کلودفلر)
۱ گیگابایت ذخیره • هر مقدار حداکثر ۲۵MiB • ۱۰۰۰ نوشتن در روز • ۱۰۰٬۰۰۰ خواندن در روز.
ویدیوی ≈۶۰ ثانیه‌ای با crf 26 معمولاً چند مگابایت است و جا می‌شود. اگر فایلی از ۲۵MiB بیشتر شد، `kv_store.py` خطای روشن می‌دهد.

## چطور کار می‌کند
- `CF_ACCOUNTS` (GitHub Secret): آرایهٔ JSON از `{"name": "...", "token": "cfut_..."}`. هر توکن باید دسترسی **Workers KV Storage: Edit** و **Account: Read** داشته باشد.
- `tools/kv_store.py`: حساب هر توکن را خودش پیدا می‌کند، توکن‌های تکراری برای یک حساب را یکی می‌گیرد، namespace با نام `riwayat-media` می‌سازد و فایل‌ها را از **حساب اصلی** (حسابی که Worker در آن است) شروع به پر کردن می‌کند. وقتی مصرف از بودجه (پیش‌فرض ۹۰۰MB از ۱۰۲۴) بگذرد یا نوشتن رد شود (مثلاً سقف ۱۰۰۰ نوشتن روزانه)، فایل به حساب بعدی می‌رود.
- جدول «کلید ← حساب» در کلید `__registry__` حساب اصلی است. Worker (`cloudflare/worker/src/index.js`) از روی آن فایل را از حساب درست می‌خواند. مسیرها و رفتار برای برنامهٔ اندروید تغییری نکرده است.
- فایل بدون تغییر دوباره نوشته نمی‌شود (هش SHA-256)، تا سهمیهٔ نوشتن هدر نرود.

## افزودن/حذف حساب
1. GitHub ← Settings ← Secrets ← `CF_ACCOUNTS` را ویرایش کن (یک آبجکت اضافه یا کم کن).
2. ورکفلو **Deploy Cloudflare backend** را اجرا کن (فهرست حساب‌ها را به Worker می‌دهد).
3. ورکفلو **Publish episodes** را اجرا کن (فایل‌هایی که حسابشان حذف شده دوباره روی حساب‌های باقی‌مانده بارگذاری می‌شوند).
- حساب اصلی (Worker و registry) را عوض نکن مگر لازم باشد؛ اگر عوض شد، همهٔ فایل‌ها دوباره بارگذاری می‌شوند (مشکلی نیست، همه از مخزن ساخته می‌شوند).

## محدودیت‌های شناخته‌شده
- هر پخش، فایل را از API کلودفلر می‌خواند؛ Cache API روی `workers.dev` کار نمی‌کند، پس فقط کش درون‌حافظهٔ Worker هست. برای مخاطب کم کافی است؛ با رشد، دامنهٔ اختصاصی یا Workers Paid لازم می‌شود.
- API کلودفلر محدودیت نرخ دارد (حدود ۱۲۰۰ درخواست در ۵ دقیقه برای هر کاربر).
- توکن‌ها داخل secret‌های Worker هم هستند. بعد از پایان کار، توکن‌های بی‌استفاده را باطل کن.

## وضعیت راه‌اندازی (۲۱ اکتبر ۲۰۲۶)
- ۵ حساب KV فعال: حساب اصلی (Worker) + حساب‌های ۳، ۶، ۷، ۸. Worker فقط در حساب اصلی لازم است؛ بقیه فقط namespace دارند (Worker از راه API به آن‌ها می‌رسد، پس «ورکر» جدا در آن حساب‌ها لازم نیست).
- هر ۴ قسمت منتشر شد؛ ورکفلو **Smoke test (live API)** کاتالوگ، پوستر، لینک امضاشده و Range را روی Worker زنده می‌آزماید.
- توکن عمومی `Token` برای KV دسترسی ندارد (۴۰۱) و خودکار نادیده گرفته می‌شود؛ حساب آن همان حساب اصلی است.

## به‌روزرسانی (۲۱ اکتبر ۲۰۲۶): حساب اصلی بدون رسانه
- حساب اصلی (Worker + برنامه‌های اشتراک دیگر) دیگر ویدیو/پوستر/کاتالوگ نگه نمی‌دارد؛ فقط کلید کوچک `__registry__`. رسانه فقط روی حساب‌های دیگر است و با سرریز خودکار پخش می‌شود (برای بازگرداندن: `KV_PRIMARY_STORES_MEDIA=1`).
- ۱۰ توکن در `CF_ACCOUNTS`؛ نه حساب ذخیره (۳، ۴، ۵، ۶، ۷، ۸، ۹، ۱۰، ۱۹) + حساب اصلی.
- ارتقای یک حساب بعداً: فقط ترتیب/بودجهٔ حساب‌ها یا انتقال Worker لازم می‌شود؛ ساختار تغییر نمی‌کند.
